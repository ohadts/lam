# Stage 04 — Connection outputs, env rendering, `lam run`

**Goal:** the app gets wired up with zero copy-paste: `lam run -- mvn spring-boot:run` just works.
**Depends on:** 03. **Read first:** specs/03 §1 (env), specs/04 (outputs, env), specs/06 §2 (shell/signals), ADR-004.

## Deliverables
1. Output evaluation (host and internal views) after apply, using the real allocated ports. `lam outputs <instance> [key] [--internal] [--show-secrets]`.
2. Env renderers in core, each a pure function `(vars) → string`, with golden tests:
   - `dotenv`: quoting rules compatible with dotenv/Spring/Docker, multiline-safe;
   - `shell`: auto-detects bash/zsh/fish/PowerShell from `--shell` or the environment; `eval "$(lam env --format shell)"` / PowerShell `lam env --format pwsh | Invoke-Expression`;
   - `json`;
   - `spring-properties` and `spring-yaml`: the yaml form nests dotted keys correctly and adds a header comment "generated by lam — do not edit";
   - `dotnet-json`: `ConnectionStrings:Default` style → nested JSON.
3. Var assembly: manifest `env.common`/per-format blocks → per-instance prefixes → `env.include` filter → `env.vars` overrides (interpolated) → final map. Case-insensitive collision check.
4. `lam env` (print), `lam env --write` (writes all `env.outputs` atomically). `lam up` writes them automatically and prints the paths.
5. `lam run [--no-up] -- <cmd…>`:
   - ensures `up`, then spawns the command with `process.env` merged with LAM vars (LAM wins, with a warning when it overrides an existing var);
   - exit code passthrough; signal forwarding; Windows `.cmd` shim handling (specs/06 §2).
6. Docs page: "Using LAM with Spring Boot" (profile `lam`, generated `application-lam.yml`).

## Acceptance criteria
- **AC-04.1** Golden tests for each renderer, including values with spaces, quotes, `#`, `=`, newlines and unicode.
- **AC-04.2** spring-yaml of `{ "spring.datasource.url": "x", "spring.datasource.username": "y" }` nests under `spring.datasource`.
- **AC-04.3** `@docker`: `lam run -- node -e "console.log(process.env.DATABASE_URL)"` prints a URL that `pg` can connect to.
- **AC-04.4** `lam run -- node -e "process.exit(7)"` exits 7.
- **AC-04.5** Ctrl-C (SIGINT) to `lam run` reaches the child; the child's handler runs; lam exits with the child's code. Tested on Linux and macOS, and on Windows via `taskkill` fallback test (fake child).
- **AC-04.6** Windows (CI, fake runtime): `lam run -- npm --version` works (the `.cmd` shim path).
- **AC-04.7** `env.vars` referencing `${assets.db.outputs.port}` renders the real allocated port.
- **AC-04.8** Secrets: `lam env` prints real values (that is its purpose), and `lam outputs db` masks the password unless `--show-secrets`.
- **AC-04.9** `lam up` writes `.env.lam` and `application-lam.yml` for the example project, and both are listed in the summary.
